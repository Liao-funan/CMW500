SSL/TLS Handshake View

The view is displayed via the hotkey "SSL/TLS Handshake", see "Hotkeys".

SSL/TLS Handshake view

The view shows information about the SSL/TLS handshake between the client (the DUT) and the server (the destination). The handshake is done at the beginning of a secure connection.

The left part lists the values offered by the client. The right part lists the values selected by the server. The client identification and the server identification are displayed at the top of the trees.

The following handshake parameters are listed.

└ Version
└ Cipher Suites
└ Public Key Length
└ Compression
└ Signature Hash Algorithm
└ Signature Length
└ Elliptic Curves, Elliptic Curve Point Formats, Elliptic Curve Type
└ Server Name Indication, Server Type Indication
Version

The protocol version is the most important indicator for the security of a connection. Ideally, an application uses the highest version supported by the DUT, not a lower version. Any protocol version below TLS 1.1 can be considered as insecure.

Cipher Suites

A cipher suite specifies the set of used security methods / algorithms. The suites are listed in IANA notation.

Example for a cipher suite name with all possible components:

TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256

This string is explained in the following table.

Value

Information type

Purpose

TLS

Protocol

 

ECDHE

Keeping secrets (confidentiality)

RSA

128 (bit)

Public Key Length

Length of the public key of the server in bits. Long keys are more secure than short keys.

You can use the following internet resource to evaluate the key length: https://www.keylength.com/en/compare/.

Remote command: 

FETCh:​DATA:​MEAS<i>:​IPANalysis:​IPCSecurity:​CAPPlication:​HANDshake:​NEGotiated?

 
Compression

Number of the compression method. 0 means no compression.

A connection with compression is more vulnerable to attacks than a connection without compression.

Signature Hash Algorithm

Pairs of hash algorithm (for example SHA256) and signature algorithm (for example ECDSA) for digital signatures, see RFC 5246, section 7.4.1.4.1.

Server Name Indication, Server Type Indication

The server name indication (SNI) specifies the name of the server that the client wants to contact. The identification can, for example, be a hostname or an IP address.
